# 개인정보 운영 점검

확인일: 2026-10-30. 이 문서는 운영용이며 웹사이트에 배포하지 않습니다.

## 확인한 현재 동작

- 월급, 근무일, 근무시간은 브라우저에서만 사용합니다. 랭킹 저장 함수는 과거 급여 필드를 삭제하도록 작성되어 있지만, 이전 모든 문서를 일괄 정리한 것은 아닙니다.
- Firebase 익명 인증, 날짜별 UID 문서, 활동 인원 집계를 사용합니다.
- 개인 달력·리포트의 날짜별 시간과 근무 조건은 `slacker.dailyState`에, 목표 이름과 가격은 `slacker.priceGoal`에 로컬 저장합니다. Firebase에 이력을 추가 전송하지 않습니다. 리포트 이미지는 이용자가 선택한 경우만 내려받거나 외부 앱에 공유합니다.
- Firestore 기본 데이터베이스는 읽기 전용 메타데이터 조회로 `asia-northeast3`(서울)를 확인했습니다. 인증 및 호스팅 로그의 처리 위치는 별도입니다.
- 자정은 조회 날짜의 전환이며 서버 문서 삭제가 아닙니다. 활동 만료 역시 집계에서 제외할 뿐 문서를 삭제하지 않습니다.
- 서비스 코드에는 서버 기록의 기간별 자동 삭제 작업이 없습니다. 외부 TTL 정책, 제공자 로그 및 백업 보관 설정은 별도 확인 대상입니다.
- 현재 계산기 및 안내 페이지는 AdSense 요청 코드를 실행하지 않습니다. `ads.txt`와 미사용 광고 컴포넌트가 있는 것만으로 광고가 요청되지는 않습니다.
- Google Analytics 4 웹 태그를 계산기와 안내 페이지에 추가했습니다. 기존 Firebase 연결 속성 `538955745`, 측정 ID `G-E0ZB5379NR`을 사용하며 운영 호스트에서만 실행합니다. 페이지 조회·유입 정보와 타이머·저장 이벤트 이름을 보내며 Firebase UID, 닉네임, 급여·근무 조건 및 목표 정보를 사용자 지정 이벤트에 포함하지 않습니다. Google 신호 데이터와 광고 개인 최적화 신호는 비활성화합니다. 운영 수집 여부는 변경 코드 배포 후 실시간 보고서에서 확인합니다.

## 열람·삭제 문의 처리

1. 회신 주소, 요청 범위와 UID를 확인합니다. UID와 닉네임은 공개 데이터일 수 있으므로 그것만으로 소유권이 증명된 것으로 취급하지 않습니다. 확인이 불가능하면 개인정보를 추가 공개하거나 다른 이용자의 기록을 삭제하지 않습니다.
2. 이용자가 진행 중 타이머를 멈추고 저장 대기 상태를 확인하도록 안내합니다. 활성 브라우저의 저장 재시도가 삭제한 문서를 다시 만들 수 있음을 고려합니다.
3. 확인된 범위에 대해 `dailyRankings/{날짜}/users/{uid}`와 `activeSlackers/{uid}`를 점검합니다. Top 5 화면에서 보이지 않는다고 문서가 없는 것은 아닙니다.
4. 전체 삭제에는 익명 인증 계정의 처리도 별도 검토합니다. 브라우저 사이트 데이터 삭제만으로 원격 기록이 삭제되지는 않습니다. 삭제 요청에 비밀번호, 인증 토큰, 급여 원본을 요구하지 않습니다.
5. 처리 범위와 결과를 회신합니다. 제공자 로그 및 백업의 제거 시점까지 즉시 삭제로 보장하지 않습니다. 문의 메일의 후속 보관 필요성도 확인합니다.

이 문서는 수동 처리 절차이며 자동 삭제 기능이나 법률 검토를 대체하지 않습니다.

## 운영 설정에서 남은 확인

- 목적에 맞는 기록·문의 보관 기간을 정하고, 실제 자동 정리 작업을 구현한 후 공개 방침을 함께 갱신합니다.
- 과거 문서에 급여·근무 조건 필드가 남았는지 점검합니다. 기존 문서를 수정·삭제하는 작업은 별도 승인과 검증 후 진행합니다.
- Firebase Auth, Vercel 로그, 문의 이메일의 실제 보관·국외 처리 조건을 운영 계정에서 확인합니다.
- GA4 속성의 데이터 보관·향상된 측정 설정을 확인합니다. 앱에서 분석을 추가할 때 입력 필드 값이 자동 이벤트나 사용자 지정 매개변수에 들어가지 않도록 유지합니다.
- 광고 재활성화 전 제공자, 노출 페이지, 쿠키 및 해당 지역 동의 요건을 확인하고 방침과 실제 코드에 함께 반영합니다.
